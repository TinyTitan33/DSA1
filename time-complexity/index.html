Scenario 4: The Missing Master Key

The manager lost the master key! They have an unsorted ring of N keys and there are N locked doors in the hallway. They need to figure out which key opens which room.

🔄 The Trap: For every single key on the ring, the manager must test it on all N doors. That is a nested loop: N keys × N doors!

💥 The Explosion: If you double the keys and doors from 10 to 20, the effort jumps from 100 to 400 tests.

The Big-O does NOT change!
Speeding up the human doesn't change the algorithm. The number of keys (N) still dictates the worst-case scenario. Big-O measures how the required steps grow as more keys are added, not the physical hardware speed.
That is Best-Case: Ω(1).
You got lucky! But computer science plans for the absolute worst-case scenario. We have to guarantee a maximum time limit, which means assuming the correct key is the very last one we check (O(N)).
Sorting takes upfront time.
If you only need to unlock the door once, it's faster to just test them one by one. But if you have to unlock doors every single day, taking the time to organize the keys pays off forever!
